PROMPT MESTRE — SISTEMA DE PONTO FACIAL

Nome provisório: FacePonto
Plataforma: Android Tablet + Painel Administrativo Web
Backend: API própria + Supabase
Reconhecimento facial: Open Source, sem API facial paga
Objetivo: registrar, calcular e administrar jornadas de funcionários por reconhecimento facial.

1. OBJETIVO DO SISTEMA

Desenvolver um sistema de controle de ponto para empresas.

O funcionário não deve precisar digitar matrícula, CPF, senha ou tocar em opções complexas.

O funcionário simplesmente:

Chega ao tablet.
Olha para a câmera.
O sistema identifica seu rosto.
Identifica o funcionário.
Determina automaticamente o tipo da marcação.
Registra data, horário e local.
Mostra uma confirmação na tela.
Volta automaticamente para a tela de espera.

O sistema deve funcionar em dois ou mais locais físicos simultaneamente, utilizando uma única base central.

Exemplo:

Terminal 01 — Ponto de Açúcar
Terminal 02 — Santa Cruz do Capibaribe

Uma marcação feita em Ponto de Açúcar deve aparecer no painel administrativo junto com outra marcação feita em Santa Cruz.

Não criar bancos separados por local.

4. APLICATIVO ANDROID

O aplicativo deve ser desenvolvido especificamente para tablet Android.

O funcionário não deve precisar tocar em botões para bater o ponto.

5. RECONHECIMENTO FACIAL

Utilizar uma solução open source que possa ser utilizada comercialmente sem cobrança por reconhecimento.

Não utilizar:

APIs pagas por chamada;

6. ANTI-FRAUDE

O sistema deve tentar impedir que uma pessoa bata ponto utilizando:

Implementar liveness detection.

O sistema deve analisar se existe uma pessoa real diante da câmera.

Não aceitar simplesmente uma fotografia do funcionário.

Registrar ocorrências suspeitas.

Exemplo:

Funcionário: João

Uma decisão que eu manteria desde já

Eu não colocaria a lógica de “1ª batida = entrada, 2ª = saída...” diretamente no aplicativo.

O tablet apenas registra:

“João marcou às 14:02 no terminal T002.”

Quem decide se aquilo é entrada, saída, intervalo, retorno ou hora extra é o motor de jornada no backend, usando a escala do funcionário.

Isso é importante porque amanhã você pode mudar uma escala de 14h–22h para 14h–18h / 19h–23h sem precisar atualizar todos os tablets.

Esse desenho deixa o aplicativo simples e o sistema inteligente.
